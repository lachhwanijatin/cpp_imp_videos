## Client Lifecycle
* **`getaddrinfo()`**: DNS lookup.
* **`socket()`**: Creates file descriptor (Analogy: Building an unhung doorframe).
* **`connect()`**: Active open to server (Analogy: Installing the door).

## Server Lifecycle
* **`socket()`**: Creates file descriptor.
* **`bind()`**: Reserves specific IP/Port (Analogy: Reserving a restaurant table).
* **`listen()`**: Starts receiving connections (Analogy: Flipping sign to "Open").
* **`accept()`**: Creates a new file descriptor for the specific client (Analogy: Doorman letting a client in).

## Data Transfer & Buffers
* **`send()` & `recv()`**: Tell the OS to buffer bytes. `send()` returning 1500 means the OS accepted 1500 bytes, not that the network delivered them.
* **Buffer Management**: Application must track sent/received bytes via return values to avoid off-by-one errors.

## Handling Connections & Closures
* **Standard Closure**: `recv()` returning `0` indicates a graceful close by the remote peer.
* **Sending to Closed Socket**: `send()` returns `-1` (`errno = EPIPE`). Always use `send(fd, buf, len, MSG_NOSIGNAL)` to prevent `SIGPIPE` crashes.
* **Non-Blocking Checks**:
  * Use `poll()` / `epoll()` to monitor sockets asynchronously. If a socket closes, it becomes "readable" and `recv()` instantly returns `0`.
  * Use `fcntl()` to set `O_NONBLOCK`. `recv()` returns `-1` (`EAGAIN`) if empty, or `0` if closed.
